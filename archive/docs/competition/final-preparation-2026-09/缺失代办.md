## 二、P1：显著影响评审得分

### 6. 业务价值证据

- [ ] 明确用户当前完成一次市场分析所需时间和人力。
- [ ] 明确使用 FurniScope 后的目标时间和人力。
- [ ] 为每个效率提升数字注明基线、样本、计算方法和假设。
- [ ] 设计至少 3 个核心 KPI：分析周期、证据覆盖率、建议采纳率。
- [ ] 增加销量预测 KPI：MAPE/WAPE、缺货率、库存周转或预测偏差。
- [ ] 收集至少 2–3 名目标用户的访谈或试用反馈。
- [ ] 将反馈整理为可附在 PDF 末尾的证据。

### 7. 销量预测可信度

- [ ] 说明训练集、验证集和测试集的时间切分方法。
- [ ] 检查特征和数据是否存在未来信息泄漏。
- [ ] 用未参与训练的留出时间段重新评估。
- [ ] 同朴素基线比较：上一周期、移动平均、季节性基线。
- [ ] 分 SKU、站点和预测周期报告误差分布。
- [ ] 标明低数据量、新 SKU 和异常波动时的可靠度边界。
- [ ] 记录模型版本、数据截止日期和训练时间。
- [ ] 不在缺少评测证据时宣传固定 MAPE 数字。

### 8. Token Plan 模型效果评测

- [x] 已验证赛事专属网关可访问。
- [x] 已验证 `qwen3.7-plus` 和 JSON 结构化输出。
- [x] 已接入模型调用审计。
- [ ] 建立 10–20 条代表性家具分析评测样例。
- [ ] 对比 `qwen3.7-plus`、`qwen3.8-max`、`deepseek-v3.2` 等候选模型。
- [ ] 比较 Schema 通过率、事实约束、延迟和 Token 消耗。
- [ ] 确认默认模型、回退模型和兜底模型。
- [ ] 验证 429、超时、非法 JSON 和上游 5xx 的降级行为。
- [ ] 将模型选择理由写入复赛 PDF。

### 9. 前后端真实联调

- [ ] 登录页接入真实认证 API，而不是仅依赖浏览器状态。
- [ ] 分析向导接入产品、数据集、任务创建和任务启动 API。
- [ ] 执行页轮询真实任务状态。
- [ ] 报告列表和详情读取真实任务结果。
- [ ] 用户确认页面接入查询、回答和恢复 API。
- [ ] 错误提示展示服务端错误码和可重试状态。
- [ ] 移除或标注静态竞品、评论、机会评分和市场规模示例。
- [ ] 确认刷新页面后任务状态可恢复。

### 10. 真实数据边界

- [ ] 明确演示所用数据是授权数据还是 `synthetic_demo`。
- [ ] 若使用真实数据，保存授权来源和数据范围说明。
- [ ] 实现或部署 `ANALYSIS_WORKER_MODE=external` 的真实数据 Worker。
- [ ] 将产品属性、商品、评论和市场指标接入实际分析节点。
- [ ] 为报告结论建立可下钻的 Evidence Span。
- [ ] 对样本不足、数据冲突和低置信度结果触发用户确认。
