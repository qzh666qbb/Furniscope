## 重要运行说明

1. 新库只执行 `furniscope_postgresql_v3.sql`；该文件会相对包含预测迁移。`v3_api_contract_alignment.sql` 等脚本面向旧库，不应再次用于新库。
2. 已有部署升级时，先备份，再执行 `migrations/v3_runtime_alignment.sql`，为产品和数据集补充软删除字段及索引。
3. `ANALYSIS_WORKER_MODE=demo_only` 和 `token_plan_demo` 只能用于开发演示。生产环境必须使用 `external`；确定性 External 工具链已完成，生成式解释仍需部署方注入有效模型密钥。
4. Compose 不写入默认账号或默认密码。首次使用前应通过受控初始化脚本或管理流程创建租户和管理员，禁止在 SQL/Docker 镜像中硬编码密码。
5. 密钥处置人工证据填写在 `Docs/开发文档/FurniScope_密钥安全事件闭环记录.md`；账号持有人完成前不得将 T01 标为完成。

## HF 图册专项核验（2026-09-10）

- 本地 `HF catalog.pdf` 已核验：25 页、12,662,222 字节，解析器可读取全部页面并建立 76 个唯一 HF SKU 的页码/品类索引；上传上限已由 10 MiB 调整为 25 MiB，图册不再因文件大小被拒绝。
- 新增 `scripts/extract_hf_product_images.py`，从 PDF 内嵌原图和透明蒙版中自动提取全部 76 个 SKU 产品图，输出为 `frontend/public/assets/hf-products/HF-*.webp`（合计约 3.6 MiB）；工作台、最近报告与报告/洞察列表按后端返回的 SKU 展示对应图片，不再使用固定家具占位图。
- 解析服务会按待建档产品 SKU 定位图册页，避免把整本图册的多个产品混入同一画像；核心完整度只按 SKU、品类、尺寸、材质、结构、风格、颜色、目标市场八类字段计算，不以辅助元数据虚增分数。
- 官网 `http://www.hf-furniture.com/products/` 实测返回 404，HTTPS 证书校验异常。新增 `API-PRD-08` 预留入口，对该站点返回 `PRODUCT_URL_STRUCTURE_UNSUPPORTED` 和“推荐上传 HF catalog.pdf”的明确提示。
- 图册单品页主要包含产品图片、SKU 与品类标题，没有尺寸、材料和目标市场等文字事实。因此在没有 HF 规格表或视觉理解模型的条件下，不能真实宣称“单产品至少 8 个核心属性、准确率≥90%”。
- 当前工作区没有对应 HF 品类的授权市场商品/真实评论样本，运行环境也未注入新阿里云密钥；六类 External 算法的真实运行、无 Mock E2E 和三轮稳定性计时仍被这两个外部输入阻塞。

## 合成市场样本（2026-09-10）

- 用户允许基于现有预测数据生成演示样本。核验发现 `/data/projects/sales_forecast/update` 是 Amazon 灯具销售/库存数据，不是家具市场事实，因此仅用于校准合成价格分布。
- 新增 `scripts/generate_hf_demo_market.py`，固定随机种子将源数据中按销量排序的 SKU、均价和站点分布映射到 HF 图册全部 76 个唯一 SKU，生成可重复、明确标记 `demo_synthetic` 的 76 条家具商品和 1,520 条评论；产物为 `demo_data/hf_market_demo.json`，所有商品、SKU映射与评论外键关联校验通过。商品展示名统一使用“图册品类中文名 + HF SKU”（例如“带脚凳休闲椅 HF-A0049-1”），不再使用虚构的 `inspired by` 标题。
- 数据导入不再把商品品类硬编码为 `sofa`，而是使用数据集的 `category_code`；有效评论数改为导入后数据库真实计数，避免幂等重放时虚增。
- 真实向导增加产品品类代码，并确保产品与数据集使用同一品类。合成样本默认选择 `demo_synthetic`，禁止误标为授权真实数据。
- External 授权闸门支持任务级显式 `allow_generated_fixture`：仅当数据集本身标记为 `demo_synthetic` 且任务明确允许时才放行，并在运行结果中标为 `generated_fixture`；普通 External 任务仍会拒绝未授权合成数据。
- 用户在对话中提供的第三方 API Key 未写入仓库、生成脚本、样本或日志；本次本地确定性生成未调用该 Key。由于该值已出现在对话中，建议使用者旋转密钥。
