# 三、项目开发及阶段成果说明

> 项目名称：FurniScope 跨境家具超级 AI 员工  
> 更新日期：2026 年 9 月 15 日  
> 当前阶段：赛事演示版收口（第 0/1 波已完成；本轮补齐真实模型审计、本环境预测指标与死信清理）。政策源/通知渠道、监控与自动备份按计划暂不交付。

## 3.1 开发过程

FurniScope 按「业务调研 → 需求与契约 → 主链路打通 → 工程化验证 → 演示诚实收口」推进。

需求阶段围绕跨境家具企业的调研、竞品、评论、机会评分、改款建议和销量预测，把产品定义为一个企业用户即可完成「产品资料进、决策报告出」的 AI 工作台。设计阶段用 PRD/SRS、数据字典、PostgreSQL V3、REST 契约、LangGraph 工作流和页面原型锁范围，前端 React 19 + Vite，后端 FastAPI，数据 PostgreSQL，异步任务 Redis Streams，分析编排 LangGraph，销量预测 XGBoost。

开发优先贯通「产品建档 → 授权市场数据 → AI 分析 → 证据报告 → 销量预测」。随后补上 JWT 租户隔离、幂等、Worker 租约重试、人工确认和 Docker 一键启动。近一轮按赛事演示标准收口：注入 Token Plan（额度不足时对话走 DeepSeek，向量和重排仍用阿里云）、对话上下文入库、自有商品按 SKU/ASIN 精确匹配、采集零结果不得标成功、补齐机会评分/方案生成停点，并用隔离库 pytest 与 Playwright 契约固化。本轮再把报告叙述接到真实网关并写入 `ai_model_runs`，预测状态改为展示本环境回测，归档并清空 Redis 死信。密钥只在运行环境，不进 Git。

## 3.2 目前已完成的功能

**产品与企业能力。** 单条/批量建档，PDF、扫描件、Excel、图片解析生成版本化画像；材料、尺寸、MOQ、成本与制造能力可管；字段带来源、置信度和人工确认状态。

**授权市场数据。** 支持企业导出 / 授权供应商 / 公开授权包导入。HeFeng 使用授权编号 `HeFeng-AUTH-AMZ-US-SOFA-2026Q3` 的北美沙发市场包（主数据集 76 个 listing、约 1520 条有效评论），分析 `data_class` 为 `authorized_market_data`。接口拒绝再创建 `demo_synthetic`。

**AI 工作台与决策报告。** LangGraph 覆盖产品理解、竞品与评论、机会五维评分、改款建议、证据审计和报告。可停在产品 / 市场 / 评分 / 方案 / 完整报告。对话支持 `context` 消息入库；选 SKU 做范围分析后可追问。报告定量值仍来自授权数据；执行摘要由 Token Plan / DeepSeek 生成，并落库 token、时延与 provider。竞品向量匹配与重排成功时同样写入审计。

**采集、调度与竞品变更。** Redis Worker 承载分析、解析、导入、预测和采集。启动即扫到期源，之后每 30 秒维护。`fetched=0` 或无可写 ASIN/评论记 **failed**，不记 succeeded。Amazon 公开评论页在反爬/空页时按失败展示，并已停用该失败源以免重复空跑。HeFeng 授权包可通过 `pack://` 到期刷新。

**销量预测。** 已接入租户级 XGBoost 引擎，可按 SKU/站点输出预测区间、安全库存和建议产量。模型卡片优先展示本环境全量回测（约 401/1204 SKU，WAPE 约 58.1%，与四周移动平均接近），不再把文档里抄来的 14.9% MAE 当作现网指标。HeFeng 可预测 SKU 会补齐预测结果覆盖。

**工程化。** RS256 JWT、Refresh 轮换、租户行级隔离、幂等、统一错误码、审计日志。Docker Compose 含 frontend / backend / worker / postgres / redis；`/health/ready` 为 `model_router: configured`、`chat_fallback: deepseek`、`product_parse_mode: model`。CORS 读取运行环境允许来源（含局域网演示地址）。DDL 只在进程启动执行。密钥文件 `.env` / `api.md` 不进库。Redis 死信先归档再删除死信流，不 flush 业务库。

## 3.3 遇到的挑战及解决方案

### 1. Agent 设计：长流程既要可停、可恢复，又不能让大模型改写事实

跨境家具分析不是单次问答，而是产品理解 → 竞品 → 评论 → 机会评分 → 方案 → 报告的长链路。早期若做成「一个 Prompt 出全报告」，评委无法核验中间证据，失败也只能整单重跑；若每步都调大模型，又会把价格、评分、样本量改成生成式数字。

处理：用 LangGraph 把业务拆成 I00–I19 节点，PostgreSQL Checkpointer 以 `task_uuid` 为 `thread_id` 保存状态；关键边界设 `user_confirmation`（interrupt + Outbox 恢复）。工作台可把运行终点停在产品 / 市场 / 评分 / 方案 / 报告，停点走 `target_complete`，不伪造未跑节点的报告。数值、聚类、五维评分和证据 span 以 SQL/规则为准；百炼负责资料抽取、竞品 embedding/rerank 和报告叙述。阿里云额度不足时仅 Chat 回退 DeepSeek；embedding/rerank 不跨供应商。报告叙述成功或失败都写入 `ai_model_runs`，避免用 `furniscope_rules` 冒充模型审计。

### 2. 预测模型设计与训练：家具销量稀疏、口径不能抄文档

家具 SKU 季节弱、站点多、大量长尾零销。若用单一时序或把文档里的 14.9% MAE 直接贴到模型卡，无法说明本环境是否可复现。训练若混入「未来才知道」的促销/库存字段，回测会虚高。

处理：日/周两套特征（约 40 / 48 维），XGBoost 与 LightGBM 0.5/0.5 集成，输出点预测、区间、安全库存和建议产量；大模型不得改写这些数字。制品加载前做文件存在性和指纹校验。模型卡改为展示本环境 holdout（约 401/1204 有标签 SKU，WAPE 约 58.1%，与四周移动平均接近），不再使用抄录指标。HeFeng 可预测 SKU 补齐结果覆盖。更严格的因果时间窗与在售目录分层，留到有完整订单预处理后再做。

### 3. 市场洞察：授权包必须能进分析，不能「ready 但没明细」

市场洞察依赖可核验的 listing 和评论。曾出现数据集状态已是 ready、计数有了，点进分析却没有商品/评论行；也有人把授权包里的 `SYN-HF-*` 当成「这是假数据」。

处理：HeFeng 包按企业授权真源处理（授权编号 `HeFeng-AUTH-AMZ-US-SOFA-2026Q3`），分析 `data_class` 固定 `authorized_market_data`；创建 `demo_synthetic` 直接 422。导入链路做必填列、最新快照、空文本/重复/乱码/Spam 过滤，原文留在 `content_original`。空壳 ready 数据集用同一授权包补齐明细，计数与行数一致。洞察首页按「导入 → 清洗 → 用于 AI」三步展示质量，不以静态样例冒充库内规模。

### 4. 竞品分析：标题很像，但不能把自家货和竞品混为一谈

家具标题高度相似（Compact Sofa、HF-* 出现在竞品文案里）。子串匹配会把 CSV 里的竞品或标题中的型号当成本企业 SKU，后续 embedding 集合被污染，价格带和痛点会算错。公开 Amazon 页还经常返回防护页。

处理：自有商品只按 SKU/ASIN 忽略大小写精确匹配。竞品库用规则硬过滤（站点、品类）后再做 `text-embedding-v4`（1024 维）点积与 `qwen3-rerank`，与材质/风格分项合成 `overall_score`；模型不可用则降级为 token 相似度并打质量标记。监控侧保存 Listing 快照，对价格、标题、主图、卖点、促销做 diff 告警。采集 `fetched=0` 或无可写 ASIN 记 failed，不标成功；Amazon 空跑源已停用。授权包到期刷新已验证写出 `SYN-HF-001` 售价变更。

### 5. 舆情：评论要可回溯原文，不能生成一段「用户都说舒适」交差

舆情若直接让大模型总结，无法指向某条评论；重复短评和乱码会抬高「提及率」。公开评论页零结果若标成功，看板会显示虚假热度。

处理：有效评论经清洗后抽取家具领域观点（舒适、组装、气味、包装等 Taxonomy + 评分/情感规则），每条观点带可定位原文的 Evidence Span，写入 `review_aspects` / `insight_clusters`。原始评论不做翻译覆盖。实时舆情事件按内容哈希去重，正负向用评分与关键词联合判定。工作台和市场洞察展示的是聚类与证据条数，不是无出处金句。主动采评论同样遵守零结果 failed。

## 3.4 后续迭代计划

1. **政策与通知（暂缓）：** 现网政策源和通知渠道仍为 0；本轮不做。后续再接一条可投递渠道，或把入口改成与能力一致的名称。  
2. **运维加固（暂缓）：** 监控、Grafana 与自动备份本轮不做。HTTPS 与对象存储仍待生产环境。  
3. **采集增强：** 浏览器采集 Worker、分页与失败页留样，提高 Amazon 等站的可解析率。  
4. **预测深化：** 在有因果预处理和在售目录标签后，再评估是否相对移动平均有稳定优势。  
5. **试点：** 用分析周期、证据覆盖、建议采纳和预测偏差做企业试用 KPI。

## 3.5 阶段结论

FurniScope 已是可运行的前后端系统：授权市场数据进、Token Plan / DeepSeek 分析出、报告带证据与真实模型审计、预测展示本环境回测。当前版本适合赛事路演和评审复现。政策源、通知渠道、监控与自动备份明确未交付，不写入已完成能力。
