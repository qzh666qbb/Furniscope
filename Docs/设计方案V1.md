# FurniScope 家具出海产品机会雷达——设计方案 V1

## 一、项目概述

### 1.1 参赛赛道

**赛道三：AI 市场洞察**

具体聚焦方向：

- AI 评论深度挖掘；
- AI 智能选品；
- 家具产品—市场—制造能力匹配。

### 1.2 方案名称

**FurniScope——家具出海产品机会雷达**

### 1.3 一句话定位

面向中国跨境家具制造企业，利用 AI 分析海外电商商品、价格、市场表现、图片及用户评论，识别尚未被满足的消费需求，并结合企业现有产品和制造能力，输出可落地的选品、产品改进、市场定位与定价建议。

### 1.4 核心目标

系统最终帮助家具企业回答五个问题：

1. 这个产品是什么，其核心能力和成本边界是什么？
2. 海外消费者购买同类产品时最关注什么？
3. 现有竞品有哪些优势和未解决的问题？
4. 该产品最适合哪个市场、价格带和消费人群？
5. 工厂应该保留什么、修改什么、重点开发什么？

---

## 二、客户需求与业务痛点

根据家具出口企业的实际调研，客户当前的核心问题包括：

- 不知道什么产品更容易在海外市场销售；
- 不理解海外客户和消费者的真实需求；
- 新品开发可能出现审美、功能或价格与市场不匹配；
- 市场和竞品数据能力较弱，目前主要依赖人工查看 Amazon 销量、排名、评论和价格；
- 企业虽然拥有产品图片、CAD 图、参数表、报价、历史订单和邮件记录，但缺少将这些数据转化为市场决策的能力；
- 客户希望 AI 优先解决市场趋势分析和产品机会判断问题。

本项目要解决的不是单纯的文案生成问题，而是产品开发和海外销售之前的决策问题：

> 什么产品值得做？应该卖到哪里？产品需要怎样改进？

---

## 三、核心方案

用户上传一个现有家具产品的图片、参数、报价及目标国家，系统自动完成以下分析。

### 3.1 多模态产品理解

AI 识别家具品类、风格、材质、功能、尺寸、价格段和适用场景，并形成标准化产品画像。

### 3.2 海外需求洞察

分析目标市场竞品的用户评论、价格、卖点和商品表现，将评论聚类为舒适度、尺寸、材质、安装、耐用性、功能、审美等家具行业需求标签，找出高频痛点和未满足需求。

### 3.3 产品机会评分

综合市场需求、趋势变化、竞争强度、用户痛点、价格空间和企业制造适配度，对产品机会进行可解释评分。

### 3.4 产品—市场匹配

判断现有产品更适合哪个国家、消费场景、价格带和目标人群，并展示判断依据。

### 3.5 产品改进建议

将消费者需求转化为工厂可执行的尺寸、材质、功能、颜色、包装、安装方式和目标成本建议。

### 3.6 决策报告与证据溯源

生成一页式产品机会卡，展示推荐市场、用户画像、需求缺口、竞品价格带、机会评分、产品改进方向及对应评论证据。

## 四、MVP 业务闭环

```text
上传沙发图片、参数和报价
              ↓
AI 生成标准化产品画像
              ↓
选择目标市场并分析竞品评论、价格与卖点
              ↓
识别消费者高频痛点和市场需求缺口
              ↓
计算产品—市场机会评分
              ↓
输出推荐市场、目标人群、价格带及产品改进方案
```

示例输出：

> 该沙发更适合美国城市小户型市场。消费者对同类产品的主要不满集中在座深不足、安装复杂和面料难清洁；建议强化可拆洗、防污面料和模块化安装，建议零售价为 499—599 美元。

        │         │         │
┌───────▼───┐ ┌───▼──────┐ ┌─▼───────────┐
│产品理解 Agent│ │市场洞察 Agent│ │决策推理 Agent │

系统采用“确定性数据处理 + 大模型语义分析 + 规则评分”的混合架构：

- 大模型负责理解图片、评论语义和生成解释；
- 价格统计、指标计算和机会评分由程序执行；
- AI 生成的结论必须关联原始数据和评论证据；
- 数据不足时明确降低置信度，不生成确定性预测。

## 六、数据输入设计

### 6.1 企业内部数据

MVP 阶段支持：

- 产品图片；
- 产品参数表；
- PDF 产品册；
- Excel/CSV 产品清单；
- 产品报价；
- 历史订单；
- 历史客户反馈。

输入数据统一转换为标准产品画像：

```json
{
  "product_id": "SOFA-001",
  "category": "modular_sofa",
  "style": ["modern", "minimalist"],
  "materials": ["polyester", "foam", "wood"],
  "functions": ["removable_cover", "modular"],
  "dimensions": {
    "width_cm": 210,
    "depth_cm": 85,
    "height_cm": 78
  },
  "factory_price_usd": 260,
  "moq": 50,
  "target_market": ["US"],
  "certifications": [],
  "manufacturing_capabilities": [
    "fabric_customization",
    "color_customization"
  ]
}
```

### 6.2 海外公开市场数据

所需数据包括：

- 商品标题和详情页内容；
- 品牌及品类；
- 商品图片；
- 当前价格与历史价格；
- 评分和评论数量；
- 评论文本和时间；
- 商品排名或销量代理指标；
- 核心卖点；
- 上架时间；
- 促销信息。

### 6.3 数据获取策略

#### MVP 演示

使用经过脱敏和整理的样例数据集，通过 CSV/JSON 导入，保证现场演示稳定且结果可复现。

#### 企业试用

支持企业上传其已有的 Amazon 运营数据、竞品表格和第三方数据平台导出文件。

#### 后续商用

通过合规 API、授权数据服务或合作数据供应商接入。方案不依赖大规模实时爬取 Amazon，以降低稳定性、合规性和数据版权风险。

## 七、AI 工作流

### 7.1 阶段一：产品资料解析

#### 文件预处理

- 图片：压缩、去重和质量检测；
- PDF：文本和表格解析；
- Excel：字段识别和单位标准化；
- 自然语言资料：实体抽取和字段映射。

#### 多模态产品理解

使用 `qwen3-vl-plus` 分析商品图片，识别：

- 家具品类；
- 外观风格；
- 颜色与材质；
- 功能结构；
- 使用场景；
- 潜在消费人群；
- 图片中无法确定的属性。

视觉识别结果与参数表交叉校验。例如，视觉模型判断材质为“真皮”，但参数表标注为“PU”时，系统以参数表为准并记录冲突。

#### 参数结构化

使用 Qwen 文本模型将参数表、PDF 和产品描述转换为统一 JSON。

数据可信度按来源排序：

```text
结构化参数表 > 企业明确填写 > PDF 产品资料
> 图片视觉推断 > 大模型常识推断
```

每个字段保留数据来源与置信度：

```json
{
  "material": {
    "value": "polyester",
    "source": "specification.xlsx",
    "confidence": 1.0
  }
}
```

### 7.2 阶段二：竞品识别与标准化

系统根据产品画像生成竞品检索条件：

- 同品类；
- 相似功能；
- 相似风格；
- 相近价格带；
- 相同目标场景；
- 相同国家市场。

使用 `text-embedding-v4` 对企业产品和竞品的标题、卖点及参数生成向量，再使用 `qwen3-rerank` 二次排序。

竞品相似度计算：

```text
竞品相似度 =
30% × 品类相似度
+ 20% × 功能相似度
+ 15% × 风格相似度
+ 15% × 价格带相似度
+ 10% × 材质相似度
+ 10% × 使用场景相似度
```

系统将竞品区分为：

- **直接竞品**：产品、功能和价格接近；
- **标杆竞品**：价格或市场表现更高，可用于学习；
- **替代竞品**：解决相同需求，但产品形态不同。

### 7.3 阶段三：用户评论深度挖掘

#### 评论清洗

由程序完成：

- 去重；
- 语言检测；
- 垃圾评论过滤；
- 无意义短文本过滤；
- 评论时间标准化；
- 星级和商品关联；
- 多语言统一翻译或跨语言向量化。

#### 家具行业标签体系

建立家具垂直需求本体，一级标签包括：

- 舒适性；
- 尺寸与空间；
- 材质与触感；
- 结构稳定性；
- 耐用性；
- 安装难度；
- 清洁维护；
- 功能设计；
- 外观审美；
- 包装运输；
- 气味与环保；
- 性价比；
- 售后服务。

二级标签示例：

```text
舒适性
├── 座垫软硬
├── 座深
├── 腰背支撑
├── 久坐体验
└── 扶手高度

安装难度
├── 安装时间
├── 说明书清晰度
├── 零件缺失
└── 孔位偏差
```

#### 评论结构化抽取

使用 Qwen 对每条评论抽取：

```json
{
  "sentiment": "negative",
  "topics": [
    {
      "label": "comfort.seat_depth",
      "opinion": "座深过短，不适合身高较高用户",
      "severity": 4,
      "user_profile": "tall_user",
      "usage_scenario": "living_room"
    }
  ],
  "purchase_driver": null,
  "product_feature": "seat_depth",
  "evidence": "..."
}
```

#### 需求聚类

使用向量模型对评论观点进行语义聚类，再由大模型为每个聚类生成标准名称。

例如：

```text
“cushion sinks after a month”
“seat became flat very quickly”
“foam lost shape”
             ↓
座垫回弹衰减 / 海绵耐久性不足
```

#### 问题重要度

```text
问题重要度 =
提及频率
× 严重程度
× 时间新鲜度
× 跨商品覆盖率
× 数据可信度
```

评论分析需要同时考虑样本数量、评论时间、评分分布、问题涉及的商品数量及评论可信度，避免少量极端评论被放大。

### 7.4 阶段四：市场趋势与竞争分析

#### 市场需求指标

- 评论数量增长率；
- 新品数量增长率；
- 商品热度变化；
- 关键词搜索或提及趋势；
- 各功能卖点渗透率；
- 不同价格带的商品和评论分布；
- 用户需求变化趋势。

#### 竞争强度指标

- 同类商品数量；
- 头部品牌集中度；
- 高评论商品占比；
- 价格竞争程度；
- 产品同质化程度；
- 新品牌进入难度；
- 用户差评问题是否已被多数竞品解决。

#### 需求缺口识别

真正的市场机会需要同时满足：

```text
用户关注度高
+ 用户满意度低
+ 现有解决方案少
+ 存在价格空间
+ 企业具备改进能力
```

### 7.5 阶段五：企业制造能力匹配

系统从企业数据中建立能力画像：

```json
{
  "categories": ["sofa", "office_chair"],
  "materials": ["fabric", "PU", "wood"],
  "processes": ["modular_design", "foam_molding"],
  "customization": ["color", "fabric", "dimension"],
  "price_range": [120, 450],
  "moq_range": [30, 200],
  "certifications": ["BSCI"],
  "target_regions": ["US", "EU"]
}
```

系统将市场机会转换为制造要求：

```json
{
  "opportunity": "可拆洗小户型模块化沙发",
  "requirements": [
    "模块化连接结构",
    "可拆洗面套",
    "压缩包装",
    "座深80厘米以上"
  ]
}
```

制造适配度由以下维度构成：

```text
制造适配度 =
品类能力
+ 材料能力
+ 工艺能力
+ 成本适配
+ MOQ 适配
+ 认证适配
+ 交付能力
```

如果某个方向的市场机会很高，但企业不具备相应工艺或认证，系统应明确显示“市场机会高、企业适配度低”，而不是直接推荐。

## 八、产品机会评分模型

最终评分拆分为六个可解释维度：

| 维度 | 权重 | 含义 |
|---|---:|---|
| 需求热度 | 20% | 用户关注和市场需求是否足够 |
| 需求增长 | 15% | 相关需求是否呈增长趋势 |
| 未满足程度 | 20% | 现有产品是否仍存在大量问题 |
| 竞争空间 | 15% | 竞争是否过于集中或同质化 |
| 利润空间 | 10% | 目标售价与成本之间是否有空间 |
| 企业适配度 | 20% | 工厂是否具备落地能力 |

评分公式：

```text
机会总分 =
0.20 × 需求热度
+ 0.15 × 需求增长
+ 0.20 × 未满足程度
+ 0.15 × 竞争空间
+ 0.10 × 利润空间
+ 0.20 × 企业适配度
```

所有子分数归一化到 0—100，输出时同时显示总分和分项得分：

```text
综合机会评分：82/100

需求热度：88
需求增长：76
未满足程度：91
竞争空间：72
利润空间：68
企业适配度：89
```

### 8.1 关于“爆款预测”

项目不宣称可以准确预测爆款，而是通过市场需求、竞争程度和企业能力计算产品机会分数，辅助企业筛选更值得验证的新品方向。

MVP 采用可解释的规则评分模型。当积累足够历史商品数据后，可再训练 LightGBM/XGBoost 等监督学习模型。

## 九、决策报告生成

系统先由程序生成结构化分析结果，再由大模型生成自然语言解释。

### 9.1 报告结构

1. 产品概览；
2. 推荐市场；
3. 推荐消费人群；
4. 核心购买动机；
5. 用户高频痛点；
6. 竞品价格带；
7. 市场机会评分；
8. 产品优势与短板；
9. 产品改进建议；
10. 建议零售价区间；
11. 风险与待验证事项；
12. 证据来源。

### 9.2 产品建议格式

每项建议必须包含：

```text
建议：将座套改为可拆洗结构
依据：目标市场18.6%的清洁类负面评论涉及不可拆洗
影响：预计增加材料及加工成本8—12美元
优先级：高
置信度：中高
验证方式：制作样品并进行20人用户测试
```

## 十、RAG 与行业知识库

### 10.1 知识库内容

- 家具品类和功能术语；
- 常见材料及工艺；
- 家具尺寸与人体工学知识；
- 不同市场使用场景；
- 企业产品参数；
- 历史订单和客户反馈；
- 市场认证与合规资料；
- 已分析的竞品和评论。

### 10.2 检索流程

```text
用户问题
   ↓
意图识别与查询改写
   ↓
元数据过滤：国家/品类/时间/价格带
   ↓
向量召回
   ↓
qwen3-rerank 重排序
   ↓
携带证据交给推理模型
   ↓
生成带来源的答案
```

企业数据按租户隔离，避免不同企业的私有产品、报价和客户资料相互泄露。

## 十一、模型选型

| 任务 | 推荐模型 | 作用 |
|---|---|---|
| 商品图片理解 | `qwen3-vl-plus` | 识别品类、风格、材质和功能 |
| 批量字段抽取 | `qwen3.5-flash` 或同类轻量模型 | 降低评论处理成本 |
| 复杂趋势推理 | `qwen3.7-max` / `deepseek-r1` | 生成市场机会解释 |
| 报告生成 | `qwen3.6-plus` | 输出结构化决策报告 |
| 文本向量化 | `text-embedding-v4` | 评论聚类和商品匹配 |
| 结果重排序 | `qwen3-rerank` | 筛选相关竞品和证据 |
| 图片扩展能力 | 通义万相 | 非核心，可生成概念产品图 |

模型调用统一通过阿里云百炼 Model Router API。

采用模型分级策略：

```text
简单抽取 → 轻量模型
复杂聚类命名 → 中型模型
最终策略推理 → 高性能模型
```

- scikit-learn 聚类及指标计算。

### 12.3 数据存储

- PostgreSQL：产品、商品、评论和分析任务；
- pgvector：商品和评论向量；
- OSS：图片、PDF 和原始数据；
- Redis：缓存与任务状态。

MVP 阶段不需引入过多中间件，PostgreSQL + pgvector 足以支持结构化数据和向量检索。

## 十四、系统可靠性设计

### 14.1 防止大模型幻觉

- 数值由程序计算，不由模型生成；
- 模型必须基于检索到的评论和商品数据回答；
- 结论附带数据来源和样本量；
- 数据不足时明确输出“证据不足”；
- 产品参数冲突时要求用户确认；
- 所有 AI 输出通过 JSON Schema 校验。

### 14.2 置信度设计

结论置信度由以下因素决定：

- 有效评论数量；
- 数据覆盖商品数量；
- 数据时间跨度；
- 不同数据源的一致性；
- 模型抽取结果的一致性。

示例：

```text
机会评分：84
结论置信度：中等

原因：
评论样本充足，但仅覆盖美国 Amazon 平台，
尚未加入 Google Trends 和线下渠道数据。
```

### 14.3 数据安全

- 企业数据租户隔离；
- 上传文件使用临时签名地址；
- 敏感报价和订单字段加密；
- 日志中不记录原始客户资料；
- 企业私有数据默认不用于训练公共模型；
- 支持分析任务和上传文件删除。

## 十五、评测方案

### 15.1 AI 抽取效果

人工标注一批家具评论，衡量：

- 需求标签准确率；
- 情感判断准确率；
- 功能实体抽取 F1；
- 评论聚类纯度；
- 证据引用正确率。

### 15.2 推荐质量

由企业负责人或产品经理对结果打分：

- 推荐市场是否合理；
- 用户痛点是否真实；
- 产品建议是否可制造；
- 定价是否符合行业经验；
- 报告是否能够支持决策。

### 15.3 系统指标

- 单次分析耗时；
- 单条评论处理成本；
- 任务成功率；
- 报告生成成功率；
- 无证据结论比例；
- 用户完成一次分析所需操作数。

### 15.4 MVP 目标

- 评论标签准确率达到 85% 左右；
- 关键结论证据引用率达到 100%；
- 1,000 条评论分析在 5 分钟内完成；
- 企业专家对建议可用性评分达到 4/5；
- 完整分析链路能够稳定演示。

## 十九、方案创新点

### 19.1 家具垂直行业理解

项目不是通用的爆款预测工具，而是围绕沙发、办公椅等家具品类建立需求标签和产品知识体系。

### 19.2 从消费者表达到工厂行动

系统不仅总结用户评论，还将用户抱怨转化为产品结构、材料、功能、包装和成本建议。

### 19.3 市场机会与企业能力联合评估

系统同时分析市场需求与企业现有 SKU、成本、工艺和定制能力，回答“市场需要什么”和“这家工厂适合做什么”。

### 19.4 可解释和证据化

每条决策建议都能回溯到竞品、评论、价格和企业产品参数，降低 AI 幻觉带来的决策风险。

### 19.5 真实企业场景验证

方案来源于家具出口企业的实际调研，并可使用客户现有的产品图片、CAD、参数、报价、订单和邮件数据继续验证。

## 二十一、初赛技术方案精简版

> FurniScope 采用“多模态理解、行业知识库、市场数据分析和可解释评分”相结合的技术架构。用户上传家具图片、参数、报价及目标市场后，系统使用 Qwen-VL 识别产品品类、风格、材质和功能，并结合参数表形成标准化产品画像。市场侧导入合规获取的竞品、价格、商品表现及用户评论数据，使用 Qwen 完成需求标签、情感、使用场景和产品痛点抽取，通过 text-embedding-v4 进行语义聚类，并由 qwen3-rerank 筛选相关竞品和证据。系统基于需求热度、增长趋势、未满足程度、竞争空间、利润空间及企业制造适配度计算产品机会评分，再由推理模型生成目标市场、消费人群、价格带和产品改进建议。所有数值由程序计算，AI 结论均关联原始评论和竞品证据。前端采用 Next.js，后端采用 FastAPI，数据存储使用 PostgreSQL、pgvector 及 OSS，模型通过阿里云百炼 Model Router 统一调用。
