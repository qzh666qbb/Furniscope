# FurniScope 客户接入指南

更新日期：2026-10-07

## 准备数据

1. 产品资料：PDF、XLSX 或图片；至少提供 SKU、品类、尺寸、材质、结构、颜色与目标市场。纯图片且无可 OCR 文字时需另附规格表。
2. 市场数据：可导入CSV/JSON/XLSX；JSON包含`listings`和`reviews`数组。商品与评论需稳定的平台ID。
3. 授权证明：企业导出、持牌供应商或公开授权数据需填写来源和授权引用。市场数据集必须提供授权依据。

## 开通账号

通过注册申请或平台管理员开通企业user账号。用户首次登录后确认企业名称；平台管理员使用独立入口，系统不设岗位角色矩阵。

## 首次分析

1. 创建产品并上传产品资料，等待解析完成。
2. 检查字段原文与冲突，选择已核验的材质/工艺/包装/认证候选并填写依据，再保存并明确确认画像。模型置信度不代表人工确认；成本与出厂报价分别填写。
3. 创建市场数据集并导入授权数据，确认状态为 `ready`。
4. 在分析向导选择已确认画像与同市场、同品类数据集，启动任务。
5. 在报告中查看机会、建议和证据原文；数值指标由确定性程序计算，生成式解释不能覆盖证据。
6. 需要销量预测时选择有历史记录的 SKU/站点；低销量或冷启动结果应结合移动平均回退和人工判断。

## 销量数据概念

| 概念 | 说人话 | 主要操作 |
|---|---|---|
| 数据清洗 | 把原始表变成系统能确定理解的标准销量表 | 识别字段、统一日期、确认日汇总/订单明细、处理重复/取消/退货、检查缺日期和数量 |
| 产品编码对照（可选） | 告诉系统“文件里的这个SKU就是产品中心的那个SKU” | 只绑定来源SKU与产品中心SKU；编码相同会自动关联 |
| 训练预检 | 在真正训练前检查这批标准数据会怎样并入历史 | 查看日期缺口、覆盖/改写行和未关联/冲突SKU |
| 快速追加 | 模型上线后，用固定格式补充日常销量并重新训练 | 只接收严格的每日汇总XLSX，不负责复杂数据清洗 |

产品编码对照不是数据清洗。它不会修改日期、销量、库存或退货口径，只处理产品身份。只有训练范围预览检测到编码不一致、未关联或冲突时，页面才显示该区域；问题未解决时不能启动训练。

## 新用户首次建模

1. 先在“产品中心”建立标准SKU。产品中心SKU是预测系统唯一的产品身份。
2. 打开“销量预测 → 模型训练”。当前没有企业私有模型时，系统默认进入“标准数据建模”，不要从快速追加开始。
3. 上传CSV/XLSX/JSON历史销量。至少包含日期、SKU、站点和销量件数；推荐提供连续140天或20个完整自然周，不要把销售金额映射为销量。
4. 核对字段、日期格式、每日汇总/订单明细、退货前/净件数口径。不确定的日期缺口默认保留未知，系统建议不能代替企业确认事实。
5. 运行质量预检，处理错误并查看数量对账、标准样本和SHA256血缘。只有明确完整导出且持续销售时才能确认补零。
6. 确认不可变标准数据版本并预览训练范围。若来源SKU与产品中心编码相同，系统自动关联；只有发现未关联或冲突时才填写“产品编码对照（可选）”，保存后重新预览。
7. 检查合并行数、日期缺口和历史改写样本；需要覆盖历史销量时明确勾选确认，然后启动首次建模。
8. 查看排队、训练中、已发布、未达标或失败状态。成熟SKU按140天/20个完整自然周参加三个滚动窗口评测；日/周各至少一个SKU验证通过才能发布。失败或未达标不会替换当前模型。

现有参考模型不意味着已对本企业训练。新企业模型暂只学习销量历史；价格、促销和库存情景尚不支持。库存可单独上传检查，但不会自动成为销量模型特征。合成测试的精度不能作为本企业效果承诺。

在评测记录展开日/周预测，可查看每个SKU的历史长度、方法和三个窗口结果；小SKU失败同样阻止发布。稀疏销量只验证窗口总量，不能据此确定成交日期。新品、手动基线、参考SKU及超出验证跨度的预测标注未验证，不生成误差区间和自动安全库存/生产量；需要先积累真实销售，再追加建模验证。

## 模型上线后的快速追加

模型成功发布后，“模型训练”默认进入“快速追加”。它适合企业每天或每周导出已经标准化的日销量，不适合首次摸底或非标准表格。

订单文件必须是XLSX，首个工作表必须包含唯一的日期、SKU、站点、销量件数列；日期使用`YYYY-MM-DD`或Excel日期单元格；每个SKU/站点日期连续，同一天只能有一条非负汇总销量。可选库存文件同样要求XLSX及明确的日期、SKU、站点、库存列。

选择文件后，页面立即检查表头、日期、数量、重复键、日期缺口以及订单/退货明细字段。检查不通过时会列出原因并引导到标准数据建模。检查通过后还需确认“完整每日汇总、退货前售出件数、相同日期/SKU/站点以本次数据为准”，系统才提交并自动重新训练。服务端仍执行完整质量门，前端通过不代表一定发布。

在没有企业私有模型时，后端可将严格合规的快速追加文件兼容性地按`initial`处理，但页面仍推荐标准数据建模；这项容错不适用于复杂退货口径、混乱日期、缺日期或模糊字段。

## 非标准订单与多表处理

订单文件可以在“订单、仓库与成交事实”中映射订单号、行号、取消/退款状态及实际退货件数，确认整日快照口径后预检。取消订单排除；净件数扣实际退货，不用退款金额推算。完全相同的重复行可选择去重，冲突订单必须核对。仓库逐一映射站点，共享仓不拆成多国库存。单价和折扣可以留作事实审计，仍不进入当前预测模型。

需要多表核验时，先分别上传并确认销量对账表或库存快照，再在主销售文件中关联。销量差额或未匹配记录须处理后再确认；零库存期间销量需要核验缺货与快照时点。确认后的规则可保存为企业模板，下次应用后仍须预检、确认；更新同名模板保留旧修订。

## 常见问题

**产品编码对照是在做数据清洗吗？**

不是。数据清洗处理字段、日期、数量和业务口径；产品编码对照只确认来源SKU属于哪个产品中心SKU。

**Quick Append能直接训练模型吗？**

能。文件通过前端检查和服务端预检后会创建训练任务；已有企业私有模型时执行追加合并和重训，没有时兼容性地执行首次训练。模型只有在滚动评测通过后才发布。

**新用户能不能直接用快速追加？**

技术上只允许严格合规的完整历史XLSX，但不推荐。首次接入通常需要确认字段、日期缺口、退货口径和SKU身份，应使用标准数据建模。

**为什么一开始看不到产品编码对照？**

系统先清洗和确认数据，再检查产品身份。同编码会自动关联；只有训练预览发现未关联或冲突SKU时才显示配置区域，避免把可选步骤误认为每次必填。

**保存产品编码对照会改销量吗？**

不会。保存后只影响新建训练任务的产品身份，当前模型、已排队任务和标准销量版本均不改变。

## 企业策略与建议反馈

在“市场洞察 → AI智能选品”中选择均衡、需求增长或利润空间偏好，也可调整五项权重和企业影响强度。初始权重是未校准的启发式，不是普适最优模型。

展开企业事实，确认品类、出口市场、具体能力及成本/交期/MOQ条件；将必要能力随策略保存。产品成本、尺寸等在产品中心确认。保存仅影响新建分析。

查看每个机会的市场原分、企业修正分和条件检查。硬条件不满足时暂缓；资料不足显示待确认。记录采纳、拒绝或待验证及原因；处理历史可导出，用于后续专家校准和排序学习。

采纳后可记录计划、实施中、完成或放弃，并填写实际日期、观察区间和核验依据。完成后分别记录达到目标、未达到或暂不能判断。没有实施不算失败；更新采纳决定后，旧实施记录保留但不再作为当前结果标签。

可选择本企业已确认销量版本回流，来源SKU必须唯一对应机会产品、站点一致且逐日覆盖观察期。收入和费用由企业按明确币种及口径报告；系统不把观察销量或收支当作机会带来的因果收益。完整处理与实施历史可查看，“导出排序评测数据”按任务导出完整候选、截点及标签资格。

真实销售和排序效果可以先用[离线验收工具](./FurniScope_真实数据离线验收指南.md)核验；数据不足时会明确给出No-Go。工具通过不代表模型已经发布，也不代表排序模型已经训练。

## 数据质量最低要求

- 国家使用两位代码，币种使用三位代码；日期、价格、评分类型正确。
- 产品、数据集和任务的品类/平台/国家必须一致。
- 删除重复平台 ID；保留采集时间和数据范围。
- 不上传未获授权的第三方抓取数据、个人敏感信息或密钥。

## 获得帮助

反馈问题时提供页面、发生时间、任务/数据版本UUID和响应中的`X-Request-ID`。详细接入规则见[标准数据API实现说明](./FurniScope_企业决策与标准数据API实现说明V1.md)；企业API与模型数据按租户隔离，平台管理保留受信管理权限。

## 产品中心批量建档与维护

首次建模前，先确保产品中心已有标准 SKU。少量产品使用“新增产品档案”；批量产品按以下
步骤处理：

1. 点击“批量导入”，先下载当前模板，不复用历史缓存模板。
2. 查看模板版本、文件 SHA256 和 Schema SHA256；正式数据只填`Product_Master`，
   示例只看`Examples`。
3. 非标准文件可选择 Sheet 和表头行，再确认字段、单位及字典映射。系统不会猜测未知
   品类、币种或单位。
4. 默认保持“仅新增”。只有明确要覆盖名称、品类、生命周期或说明时才选择“批量更新”。
5. 运行预检，先处理阻断错误；非 sofa 的“画像能力未验证”是警告，不阻止建档。
6. 在前20行预览中修正错误，或下载错误 Excel 按原行号、错误码和修复建议处理。
7. 核对有效、错误、警告、创建和更新数量，确认当前预览 SHA 后再提交。
8. 提交完成后刷新产品列表。SKU 别名、SPU、套装和 BOM 关系会与主档在同一事务写入；
   任一项失败都不会留下部分成功数据。

模板必填`SKU/产品名称/品类代码`。SKU 必须使用文本单元格，避免前导零丢失；租户内按
去首尾空格且大小写无关比较，因此`abc-01`与`ABC-01`视为同一 SKU。尺寸、重量和出厂价
存在时，必须同时提供对应单位或币种；数值不得为负；正式导入区不得使用公式。

`SKU_Alias`只做来源编码到产品中心 SKU 的一一对应，不修改销量或产品 SKU。
`Dictionaries`是唯一受控代码来源。已完成、阻断或失败任务可从最近任务继续查看；上传
中断但服务端尚未生成任务时，使用同一文件重新上传。

产品详情支持修改 SKU、品类、生命周期和说明。品类变化后原画像不再直接视为可用，
需要重新维护或确认；归档会从正常列表移除产品并解除预测别名。库存摘要是
`inventory_facts_daily`中已确认版本的最近历史快照，明确不是实时库存；库存文件仍从
独立数据链路导入，编辑产品档案不会改写库存。
