| 项目 | 内容 |

## 1. 执行结论

1. **XGBoost 应加入 FurniScope。**它不是替代大模型或六维机会评分，而是超级 AI 员工可调用的确定性销量预测工具。
2. **机会评分与销量预测并存。**六维机会评分回答“市场机会是否值得做、是否适合企业”；XGBoost 回答“在给定 SKU、站点、周期和场景下预计卖多少”。两者不得合并成一个分数。
3. **保持一个 user 驾驭一个超级 AI 员工。**不新增数据科学家、预测专员或供应链岗位角色；系统权限仍只有 `user/admin`。
4. **销量预测进入 P0 业务闭环。**允许从 AI 对话或新建分析向导触发，并在“市场洞察”的销量预测 Tab 和“决策报告”的制造适配部分查看。
5. **不新增一级“销量预测”主导航。**UI V2 的持久规则已明确销量预测属于 Market Insights；独立预测页面可以作为洞察内工具态或深链路，不增加核心页面数量。
6. **预测加入 LangGraph `researching_market` 阶段。**作为条件并行分支运行；不改变对外五阶段枚举。
7. **XGBoost 原始预测值不可由 LLM 修改。**LLM 只能解释特征影响、风险和业务含义；置信区间、误差指标、安全库存和生产建议由确定性程序计算。
8. **当前仓库没有发现训练模型产物。**尚未发现 `.json/.ubj/.bst/.pkl/.joblib` 等 XGBoost 模型文件，因此真实推理代码接入暂未满足条件。

## 4. XGBoost 在产品中的准确定位

### 4.1 业务目标

针对具备历史销售数据的商品，在明确市场、站点、SKU、预测粒度、预测周期和场景后，输出销量预测、区间、模型质量和生产计划参考。

系统不得将预测描述为确定销量、爆款保证或自动备货指令。预测是决策输入，user 对备料、排产和库存行为负责。

### 4.2 三种入口

| 入口 | 交互 | 后端复用 |
|---|---|---|
| AI 对话 | user 提出“预测未来12个月销量”；AI 检查是否有合格历史数据 | 创建统一 `forecast_job` |
| 新建分析向导 | 市场数据步骤启用预测并设置粒度、周期、场景和区间 | 分析任务关联 `forecast_job` |
| 市场洞察 | “销量预测”Tab 无结果时显示“发起预测”，有结果时显示最新可用版本 | 查询/创建统一 `forecast_job` |

不为三种入口实现三套预测逻辑。

### 4.3 用户输入

- 产品和已确认产品画像版本；
- 已授权历史销售数据集；
- 目标国家、平台、站点和 SKU 范围；
- 粒度：周或月；
- 预测周期：例如未来8周或12个月；
- 场景：`conservative/base/optimistic`；
- 置信水平：80%、90%或95%。

客户端不得提交 `tenant_id`、模型文件路径、任意特征表达式或服务器执行参数。

### 4.4 最低数据要求

训练模型的实际契约优先于 UI 示例。正式接入前至少确定：

- 必需列：日期、SKU、Site/市场、目标销量；
- 条件特征：价格、库存、促销、产品属性、评论情绪、季节因素；
- 允许的时间频率和缺失策略；
- 支持的家具品类、国家、平台与 SKU 冷启动规则；
- 最小历史窗口；
- 币种、时区、销量口径和退货处理规则。

UI 文档中的“至少8周日度历史”只能作为候选规则，必须由训练特征和回测结论确认后才能进入正式校验。

### 4.5 系统输出

- 每个 SKU × Site × 时间桶的点预测；
- 预测下界和上界；
- 预测总量、同比/环比（基线存在时）；
- MAPE、WAPE、MAE/RMSE 中模型实际支持的指标；
- 训练/回测时间范围、样本量和数据质量；
- 特征贡献或驱动因素（模型支持且解释方法固定时）；
- 推荐生产量、安全库存、分批排产建议；
- 模型版本、特征版本、输入数据哈希、推理时间和适用范围；
- 风险、限制和待验证事项。

## 5. 预测计算边界

| 结果 | 计算主体 | 约束 |
|---|---|---|
| 点预测 | 已训练 XGBoost 模型 | 不允许 LLM 修改 |
| 特征处理 | 固定版本 Feature Pipeline | 训练与推理必须同构 |
| MAPE/WAPE 等 | 确定性评估程序 | 分母为0的规则必须固定 |
| 预测区间 | 固定校准/残差方法 | 不能把模型置信度直接冒充统计区间 |
| 安全库存 | 确定性库存规则 | 必须输入服务水平、提前期和误差参数 |
| 建议生产量 | 预测量+库存+在途+安全库存规则 | 缺少库存事实时只输出条件建议 |
| 业务解释 | LLM | 只能引用已冻结的结构化结果和证据 |
| 机会评分 | 现有六维评分引擎 | 与预测结果分别展示、分别版本化 |

UI 中的 `MAPE 8.7%`、预测销量、同比、生产量和安全库存当前均为演示值；只有与实际模型评测和输入数据对应后才能作为真实结果展示。

## 6. LangGraph 工作流同步

### 6.1 节点位置

在现有 I12 Parallel Analytics Fork 增加条件分支：

```text
I12-A Price & Competition
I12-B Trend
I12-C Enterprise Fit
I12-D Demand Forecast（仅启用预测且数据合格时）
          ↓
I13 Analytics Join
```

`I12-D` 属于内部节点，外部阶段仍为 `researching_market`。不新增第六个用户阶段。

### 6.2 分支规则

- 未启用预测：`skipped/not_requested`，不算失败；
- 启用但缺少必需数据：阻断创建或触发 `user_confirmation(data_insufficient)`；
- 数据可用但部分 SKU 不满足条件：允许 `partial_succeeded`，明确被排除范围；
- 模型文件/特征版本不存在：`failed`，不得使用 LLM 伪造预测；
- 预测失败不应伪装成完整报告；是否继续主链由任务配置和预测重要性决定；
- 相同 `model_version + feature_version + input_dataset_hash + parameters_hash` 必须复用成功结果。

### 6.3 State 只保存引用

Agent State 建议增加：

- `forecast_requested`；
- `forecast_job_uuid`；
- `forecast_run_uuid`；
- `forecast_status`；
- `forecast_summary_ref`；
- `forecast_quality`；
- `forecast_partial_failures`。

逐时间桶预测、大数组、模型文件和原始销售数据不得进入 LangGraph State 或 Checkpoint。

## 7. 数据库同步范围

建议采用适度范式，新增以下 P0 实体：

| 实体 | 职责 | 关键约束 |
|---|---|---|
| `forecast_models` | admin 注册模型版本、特征版本、适用范围、文件校验和、指标和状态 | 不存任意可执行代码；模型 URI 不向 user 返回 |
| `forecast_jobs` | user 的预测请求、范围、参数、状态、幂等键及任务关联 | `tenant_id + idempotency_key` 唯一 |
| `forecast_runs` | 一次实际推理、输入哈希、模型/特征版本、质量指标、状态和错误 | 成功运行按输入版本组合唯一 |
| `forecast_results` | SKU × Site × 时间桶的预测值和区间 | job/run/tenant 联合外键；时间桶唯一 |
| `stock_recommendations` | 汇总预测、现有库存、在途、服务水平、建议生产量和安全库存 | 无库存事实时状态为条件建议，不填伪数值 |

全部业务表必须包含 `tenant_id`；所有查询由服务端认证上下文注入租户范围。模型文件进入受控对象存储，数据库只保存 URI、SHA-256、格式、版本和元数据。

## 8. API 同步范围

建议新增 P0 Forecast API，正式编号需在 API V3 修订时锁定：

| 建议编号 | 方法与路径 | 作用 |
|---|---|---|
| `API-FRC-01` | `POST /api/v1/forecast-files:validate` | 上传/引用销售文件并执行安全、Schema 和质量检查 |
| `API-FRC-02` | `POST /api/v1/forecast-jobs` | 创建预测任务；要求 `Idempotency-Key` |
| `API-FRC-03` | `POST /api/v1/forecast-jobs/{forecast_job_uuid}:start` | 异步启动；不得阻塞 HTTP |
| `API-FRC-04` | `GET /api/v1/forecast-jobs` | 查询当前租户预测历史 |
| `API-FRC-05` | `GET /api/v1/forecast-jobs/{forecast_job_uuid}` | 查询状态、质量和失败范围 |
| `API-FRC-06` | `GET /api/v1/forecast-jobs/{forecast_job_uuid}/result` | 查询预测曲线、指标和生产建议 |

分析任务创建请求可增加可选的 `forecast_config`，但不得由前端提交模型路径或 `tenant_id`。API-INS-04 聚合结果增加 `forecast_summary` 和下钻链接，不重复推理。

“同步洞察”不需要复制预测数据：通过任务/产品/市场关联预测版本即可。报告文件导出仍不属于本次 XGBoost 接入范围。

## 9. UI 功能同步

### 9.1 新建分析

市场数据步骤增加：

- 是否启用销量预测；
- 销售数据集及质量状态；
- 粒度、周期、场景、置信水平；
- 实际模型版本和适用范围；
- 回测指标与口径；
- 数据不足、字段缺失和范围不支持提示。

不得固定展示“XGBoost v4 / MAPE 8.7%”，必须来自 Forecast API 的模型元数据和真实评测。

### 9.2 AI 执行中

- 外部仍展示五阶段；
- “研究市场”阶段可显示业务级子摘要“正在进行销量预测”；
- 技术详情抽屉可显示 `forecast_job_uuid`、模型版本、重试和脱敏错误；
- 不展示模型文件路径、内部特征值、密钥或隐藏推理过程。

### 9.3 市场洞察

新增“销量预测”Tab：

- 预测范围、周期和场景；
- 历史值与预测曲线；
- 区间带；
- 总预测量和增长率；
- MAPE/WAPE 等实际指标；
- 驱动因素；
- 生产量、安全库存、分批建议；
- 风险、数据缺口和模型适用范围；
- 模型/特征/数据版本。

### 9.4 决策报告

制造适配章节引用冻结的 `forecast_run_uuid`，展示预测摘要、生产计划、库存风险和验证建议。报告不得重新调用模型或重新计算关键数字。

## 10. 测试同步范围

P0 至少覆盖：

1. 合法历史数据预测成功；
2. 必需字段缺失、MIME伪装、重复行和时间断档；
3. 不支持的品类、市场、频率和预测周期；
4. 训练/推理特征顺序一致；
5. 模型 SHA-256 和版本校验；
6. 相同输入幂等复用；
7. 同 Key 不同参数冲突；
8. 跨租户模型运行和结果隐藏；
9. 单 SKU 失败形成部分结果；
10. Worker 重启后不重复推理；
11. 指标、区间、库存公式可复算；
12. LLM 解释不改变模型原始值；
13. 洞察与报告引用同一预测版本；
14. 日志不包含销售明细、模型文件或密钥；
15. 模型不可用时明确失败，不生成固定演示值。

## 11. 训练模型接入所需交付物

当前仓库未发现训练模型文件。接入前需要提供：

| 交付物 | 必需内容 |
|---|---|
| 模型文件 | 推荐 XGBoost 原生 JSON/UBJ；说明加载版本 |
| 特征契约 | 特征名、顺序、类型、单位、缺失默认值、类别编码和派生公式 |
| 预处理产物 | Encoder、Scaler、类别字典等；不得依赖未版本化 Python 对象 |
| 目标定义 | 销量口径、粒度、退货/取消处理和预测 horizon |
| 适用范围 | 支持的家具品类、国家、平台、站点和冷启动边界 |
| 训练元数据 | 训练截止日、样本范围、代码版本、随机种子和数据版本 |
| 评测报告 | 时间切分方式、MAPE/WAPE 等指标、分市场/品类表现和基线对比 |
| 区间方法 | 残差/分位数/校准方法和覆盖率验证 |
| 示例数据 | 一份脱敏合法输入和预期输出，用于契约测试 |
| 依赖版本 | Python、xgboost、pandas/numpy 及序列化兼容要求 |

不建议只提供 `.pkl` 而不提供训练环境和特征管道；这会产生反序列化安全与版本兼容风险。

## 12. 跨文档修订顺序

XGBoost 进入正式开发基线前，按以下顺序增量修订，不覆盖旧版本：

1. PRD：新增销量预测业务目标、边界、功能和验收；
2. 数据字典：新增 Forecast 实体、字段、状态、枚举和 Agent/API 投影；
3. PostgreSQL：新增表、约束、索引及可回滚迁移；
4. Agent：新增 I12-D 分支、State 引用、失败与恢复规则；
5. API：锁定 API-FRC 编号、请求响应、错误码、幂等和权限；
6. 页面原型：同步向导、执行中、洞察和报告；
7. Mermaid：更新架构、ER、业务流与节点映射；
8. 测试：新增预测功能、安全、模型契约和恢复用例；
9. 一致性校验：建立页面→API→字段→数据库→Agent→测试追踪矩阵；
10. 代码：在契约 PASS 后实现 Forecast Service、Worker、Repository 和 Agent Tool。

## 13. 当前阻断与关闭条件

| 编号 | 阻断 | 影响 | 关闭条件 |
|---|---|---|---|
| FRC-B01 | 仓库中无训练模型产物 | 无法实现真实推理 | 提供模型文件及 SHA-256 |
| FRC-B02 | 无正式特征契约 | 无法保证训练/推理一致 | 提供字段、顺序、类型、编码、缺失和派生规则 |
| FRC-B03 | 适用范围未锁定 | 无法做输入拒绝和风险提示 | 明确品类、市场、平台、粒度和 horizon |
| FRC-B04 | MAPE 8.7% 缺评测依据 | UI 只能视为演示值 | 提供回测数据、切分方法和指标报告 |
| FRC-B05 | 预测区间和库存公式未锁定 | 无法安全输出区间/备货量 | 提供区间算法、服务水平、提前期和库存公式 |

以上阻断不影响现有市场洞察主链运行，只阻断“真实 XGBoost 销量预测”对外宣称完成。
