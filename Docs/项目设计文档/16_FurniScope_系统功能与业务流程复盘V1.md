## 1. 目标、方法与口径

本次复盘检查五条链路是否一致：

1. 需求文档和总体设计是否定义同一业务边界。
2. 前端文案、交互和状态是否准确表达后端能力。
3. API、服务和数据库是否执行同一业务规则。
4. 报告及市场结论是否来自冻结证据，而不是展示层临时推算。
5. 自动化测试和运行截图是否覆盖并证明上述契约。

主要依据：

- `01_产品需求规格说明书SRS_PRD_V2.md`
- `07_FurniScope页面交互原型说明V3.md`
- `09_FurniScope测试用例V2.md`
- `15_FurniScope_企业决策与数据闭环总体设计V1.md`
- `frontend/src/`、`backend/furniscope_api/`、`migrations/`、`tests/`
- `artifacts/system-review-20261007-fixes/`

严重度沿用首次复盘口径：

| 等级 | 定义 | 关闭要求 |
|---|---|---|
| P0 | 会生成无证据业务数字、混算不可比数据或破坏核心决策可信度 | 代码、测试和冻结证据同时完成 |
| P1 | 核心流程契约冲突、数据关联错误、状态不同步或关键页面不可用 | UI、API、数据库语义一致 |
| P2 | 功能不完整、容易误解、边界未呈现或重要体验缺陷 | 功能或明确边界交付 |
| P3 | 局部一致性、重复入口或低风险视觉问题 | 页面行为和文案一致 |

## 5. 业务SOP整改结果

### 5.1 产品主数据

```text
建立产品主档
-> 确认产品事实和版本
-> 使用稳定产品身份维护可变SKU
-> 原子同步销量、库存、目录和别名
-> 启动分析或预测
```

SKU仍是可编辑业务编码，但v3.34将改码收口到受控数据库事务，并保留旧编码追溯。

### 5.2 销量训练

```text
上传原始文件
-> 数据清洗和业务口径确认
-> 产品编码对照
-> 确认不可变标准版本
-> 预览首次/追加/重建
-> 显式确认同键改写
-> 逐SKU滚动评测
-> 达标后原子发布
```

首次建模和追加模式根据私有部署决定；页面确认、请求参数和服务端覆盖规则已统一。

### 5.3 市场定价

制造单位成本、落地成本、出厂报价和市场价格保持独立，所有金额携带币种。缺少已确认
成本时只能输出市场价格锚点；多币种数据直接阻断；评论代理不得描述为真实价格弹性。

### 5.4 报告冻结与归档

报告展示层只格式化服务端冻结事实，不补算金额、不重选主机会、不填默认场景。归档操作
统一归档报告、任务和工作台投影，首页与工作日记读取同一状态。

### 5.5 企业账号生命周期

租户和账号保持两层模型。关闭租户记录账号状态快照；恢复时只恢复关闭前为active的账号。
管理员列表逐账号分页，模型和授权仍按租户聚合。

### 5.6 合规政策监控

```text
安装默认官方源或新增已授权官方源
-> 启用并同步
-> 按当前市场和品类生成政策预警
-> 按风险等级和未读状态筛选
-> 查看官方原文并标记已读
-> 通过通知渠道投递
```

来源最近同步时间、成功/失败状态和错误信息直接读取服务端，不由前端模拟。

### 5.7 知识库检索验真

```text
上传文档并完成索引
-> 在当前知识库输入业务问题
-> 混合检索和相关度阈值过滤
-> 无可靠证据时拒答
-> 展示文档、版本、页码、原文片段和Citation
-> 打开命中文档复核
```

管理页检索与Agent使用同一`POST /api/v1/knowledge-bases:search`契约，不以文档数量代替可召回性。
