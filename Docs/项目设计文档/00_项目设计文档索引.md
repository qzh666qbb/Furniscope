## 5. 当前开发基线规则

1. 系统角色只允许 `user` 和 `admin`。
2. 产品形态为“一个 user 驾驭一个跨境家具超级 AI 员工”。
3. 对外任务阶段固定为 `understanding_product`、`researching_market`、`evaluating_opportunity`、`generating_recommendation`、`completed`。
4. 人工中断统一使用 `user_confirmation`，通过 LangGraph Checkpoint 与 `Command(resume=...)` 恢复。
5. 数据库以 PostgreSQL V3 文档和 `furniscope_postgresql_v3.sql` 为准。
6. API 以 V3 为准，页面以 V3 为准，验收测试以 V2 为准。
7. Listing、验证任务、多人评审和产品事件不属于核心产品基线；企业反馈及标准数据审计导出按15号增量设计实现，不扩大为跨平台发布。
8. 保留租户隔离、证据链、模型追溯、任务幂等、部分失败、Checkpoint 和安全恢复能力。
9. FastAPI接入的认证、ETag、幂等、JSON校验、技术详情和Outbox边界遵循[`FurniScope_FastAPI接入契约收口决策V1.md`](../开发文档/FurniScope_FastAPI接入契约收口决策V1.md)。
10. 开发期可使用明确标记的`demo_synthetic/synthetic_demo`数据；不得作为真实市场事实，production禁止启用合成适配器。
11. 前端技术栈为 `React 19 + Vite`；现有 `frontend/` 作为视觉与组件实现起点，业务范围仍以 PRD/API/页面 V3 为准。
12. XGBoost 销量预测按[`13_FurniScope_UI_V2与XGBoost功能同步方案V1.md`](./13_FurniScope_UI_V2与XGBoost功能同步方案V1.md)纳入P0增量范围；保持外部五阶段和现行七个企业一级入口，真实推理完成前不得使用UI演示数值作为模型结果。
13. 决赛完善按[`14_FurniScope_决赛完善升级方案V1.md`](./14_FurniScope_决赛完善升级方案V1.md)推进；其中算法、指标和业务收益目标只有在锁定数据集、可复现评测和关联设计文档同步完成后，才能变更为已实现事实。
14. 企业个性化评分、数据接入和预测训练按[`15_FurniScope_企业决策与数据闭环总体设计V1.md`](./15_FurniScope_企业决策与数据闭环总体设计V1.md)补全；机会排序与销量预测分别验收，默认启发式和工程测试不构成真实企业效果证据。
15. 智能问数P0只允许受控`DataQueryPlan`和固定SQL指标表达式；自由NL2SQL未开放。工作流只接受服务端`run_workflow`动作，RAG证据低于阈值必须拒答。
16. Web AI员工按[`17_FurniScope_AI员工系统与桌面端总体设计V1.md`](./17_FurniScope_AI员工系统与桌面端总体设计V1.md)实施；现有五阶段图作为领域Skill保留。确定性Goal/Plan/Run和固定Tool链已形成本地工程基线；动态Tool选择、自动重规划和定时触发仍不得作为已实现能力。
17. 桌面端按[`18_FurniScope_桌面端未来规划V1.md`](./18_FurniScope_桌面端未来规划V1.md)作为后续独立项目推进；Web Runtime通过启动门槛前不进入产品实施。MCP Host、Tauri桌面端、本地Bridge和本地计算机操作均不得作为当前能力。
