## 5. 当前开发基线规则

1. 系统角色只允许 `user` 和 `admin`。
2. 产品形态为“一个 user 驾驭一个跨境家具超级 AI 员工”。
3. 对外任务阶段固定为 `understanding_product`、`researching_market`、`evaluating_opportunity`、`generating_recommendation`、`completed`。
4. 人工中断统一使用 `user_confirmation`，通过 LangGraph Checkpoint 与 `Command(resume=...)` 恢复。
5. 数据库以 PostgreSQL V3 文档和 `furniscope_postgresql_v3.sql` 为准。
6. API 以 V3 为准，页面以 V3 为准，验收测试以 V2 为准。
7. Listing、文件导出、验证任务、多人评审和产品事件不属于核心产品基线。
8. 保留租户隔离、证据链、模型追溯、任务幂等、部分失败、Checkpoint 和安全恢复能力。
9. FastAPI接入的认证、ETag、幂等、JSON校验、技术详情和Outbox边界遵循[`FurniScope_FastAPI接入契约收口决策V1.md`](../开发文档/FurniScope_FastAPI接入契约收口决策V1.md)。
10. 开发期可使用明确标记的`demo_synthetic/synthetic_demo`数据；不得作为真实市场事实，production禁止启用合成适配器。
11. 前端技术栈为 `React 19 + Vite`；现有 `frontend/` 作为视觉与组件实现起点，业务范围仍以 PRD/API/页面 V3 为准。
12. XGBoost 销量预测按[`13_FurniScope_UI_V2与XGBoost功能同步方案V1.md`](./13_FurniScope_UI_V2与XGBoost功能同步方案V1.md)纳入P0增量范围；保持外部五阶段和6+1页面结构，真实推理完成前不得使用UI演示数值作为模型结果。

## 6. 目录维护规则

- 项目设计文档根目录只保留本索引和当前有效文档。
- 同类文档产生新版本并通过一致性校验后，旧版本移动到 `归档/旧版本/`，不得删除。
- 独立的版本变更表和对齐明细表存放到 `版本变更清单/`。
- SQL 文件保留原有历史版本；当前执行入口必须在本索引中明确标记。
- 新版文档未完成跨文档一致性校验前，不得替换当前开发基线。
