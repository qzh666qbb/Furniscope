# SKU 预测工具 V4 使用说明

> 适用版本：销量预测 V4  
> 更新日期：2026-08-25  
> 当前测试数据截止日期：2026-06-23（可使用 `update/append_test` 中 2026-06-24 至 2026-06-30 的文件测试追加，以页面实际状态为准）

## 1. 工具用途

本工具用于按 `SKU + 站点` 预测未来销量，支持一次输入多个 SKU、选择多个站点，并支持三种使用方式：

| 使用方式 | 适用场景 | 需要填写 |
| --- | --- | --- |
| 天预测 | 补货、排期，查看逐日波动 | SKU、站点、预测天数 |
| 周预测 | 周度备货、采购计划 | SKU、站点、预测周数 |
| 复杂业务预测 | 评估价格、折扣、库存、促销或新品 | 基本字段，以及需要模拟的业务参数 |

模型和历史数据已保存在服务端。日常预测不需要再上传历史文件。

## 2. 访问地址与页面状态

- 公网地址：<http://1.15.86.127:8088>

打开页面后，右上角会显示模型状态：

- `模型就绪 · 数据至 YYYY-MM-DD`：日模型和周模型均可使用；日期是系统内最新订单数据日期。
- `模型尚未训练完整`：至少有一个模型还没有训练完成。
- `模型未初始化` 或一直显示正在连接：数据状态或后端服务异常，请联系管理员并查看后台日志。

![V4 销量预测首页](docs/images/v4-forecast-page.png)

页面顶部有两个主功能页签：

- **销量预测**：选择天预测、周预测或复杂业务预测。
- **模型训练**：追加最新订单/库存数据，并重新训练模型。

## 3. 普通预测

### 3.1 天预测

1. 进入“销量预测”，选择“天预测”。
2. 输入一个或多个 SKU，例如 `YU298B`；多个 SKU 可使用空格、逗号、分号或换行分隔。
3. 点击选择一个或多个站点，例如同时选择 `US` 和 `CA`。蓝色表示已选择，再次点击可取消，但至少需要保留一个站点。
4. 输入预测天数，范围为 1～365 天，常用值为 7。
5. “起始日期”可留空；留空时系统会从历史数据末尾之后开始预测。
6. 点击“开始天预测”。

天预测会返回每天的预测销量、下界和上界，适合观察星期差异及短期波动。

### 3.2 周预测

1. 选择“周预测”。
2. 输入一个或多个 SKU，选择一个或多个站点，并填写预测周数，范围为 1～52 周。
3. 起始日期可留空。指定日期时，周预测会自动按该日期所在周的周一对齐。
4. 点击“开始周预测”。

周预测直接返回每周汇总销量，适合周度采购和备货。

### 3.3 基本字段说明

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| SKU | 是 | 可输入一个或多个 SKU；多个 SKU 用空格、英文逗号、中文逗号、分号或换行分隔，也可从浏览器建议列表中选择 |
| 站点 | 是 | 支持多选 `US、CA、DE、FR、IT、ES、NL`，蓝色按钮表示已选择，至少选择一个 |
| 预测天数/周数 | 是 | 天预测最多 365 天，周预测最多 52 周 |
| 起始日期 | 否 | 建议通常留空；用于指定未来计划开始时间 |

如果普通预测提示“未找到 SKU/站点”，先检查 SKU 拼写和站点是否匹配。没有历史数据的新品应使用复杂业务预测。

多选时，系统按照“SKU × 站点”生成全部组合。例如输入 2 个 SKU 并选择 `US、CA`，会提交 4 个 SKU/站点组合。除非使用新品基准或参考 SKU，否则每个组合都必须存在历史数据；任一组合不存在时，页面会列出缺失组合，请取消对应站点或调整 SKU。

## 4. 复杂业务预测

复杂业务预测用于“如果价格、库存或促销发生变化，销量可能是多少”的情景模拟。选择后，还需选择“按天预测”或“按周预测”。所有复杂参数都可以留空，留空时使用历史默认值。

| 参数 | 填写方式 | 作用 |
| --- | --- | --- |
| 计划售价 | 大于等于 0，例如 `20` | 模拟未来售价变化 |
| 折扣力度 | 0～1，例如 `0.15` 表示 15% | 模拟折扣变化 |
| 当前库存 | 非负整数，例如 `45` | 预测销量会受可售库存约束 |
| 促销流量倍数 | 例如 `1.5` | 填写即表示参加促销；留空表示无促销 |
| 新品基准日销量 | 例如 `3.5` | 无历史 SKU 的冷启动基准 |
| 参考 SKU | 一个已有 SKU | 新品借用相似老品的销售模式 |

复杂测试示例：

| 字段 | 测试值 |
| --- | --- |
| SKU / 站点 | `YU298B` / `US` |
| 粒度 / 周期 | 按周 / 4 周 |
| 起始日期 | `2026-07-06` |
| 计划售价 / 折扣 | `20` / `0.15` |
| 当前库存 | `45` |
| 促销流量倍数 | `1.8` |

点击预测后，重点检查：有结果、日期连续、促销参数被接受，并且受库存约束时累计预测销量不应超过 45。模型重新训练后具体预测数值可能变化，所以不应把某个固定销量作为测试通过条件。

新品测试时，可输入一个系统中不存在的新 SKU，并至少填写“新品基准日销量”或“参考 SKU”。

## 5. 结果怎么看

结果区分为摘要和逐期明细；批量预测时，每个 SKU/站点组合分别显示一张摘要卡片，逐期明细合并展示：

- **预测总量**：本次所选预测周期内的销量合计。
- **日均销量**：预测总量折算后的日均值。
- **置信区间**：模型估计的合理波动范围，不是绝对保证。
- **可靠度 A～D**：A 相对最可靠，D 表示历史较少、波动较大或预测条件偏离历史，应谨慎使用。
- **下界/上界**：仅天预测逐日展示，用于制定保守或宽松备货方案。

可以点击“导出 CSV”或“导出 JSON”保存全部已选 SKU/站点组合的结果。建议采购计划同时参考预测值、上界、库存和运输周期。

CSV 文件字段说明：

| 字段 | 含义 |
| --- | --- |
| `预测销量` | 当前 SKU、站点和时间桶的点预测值 |
| `下界` / `上界` | 预测波动区间的下限和上限；日预测按每个日期计算，周预测明细没有逐周区间时留空 |
| `销量预测区间` | 将下界和上界合并展示为 `下界 ~ 上界`，便于直接阅读 |
| `可靠度值` | A、B、C、D 四档可靠度，A 相对最可靠，D 表示历史较少或波动较大 |

上下界是基于历史销量波动估计的合理范围，不是销量保证，也不等同于统计置信度。当前日预测使用近期历史标准差计算区间，并将下界限制为不小于 0；可靠度综合历史长度和变异系数判断。

## 6. 追加数据与重新训练

进入“模型训练”页签后需先登录。当前测试账号为 `SKUadmin`，密码为 `sku123`，登录有效期为 8 小时。

进入“模型训练”页签后，可以看到两个文件框和四个操作按钮。

### 6.1 两个文件是否都要上传

- **订单数据：必传。**“追加数据”按钮只有选择订单文件后才能点击。
- **库存数据：可选。**同期有库存更新时一起上传；没有库存文件时只传订单即可。
- 当前页面不支持只追加库存、不追加订单。

点击整个文件框即可选择 `.xlsx` 文件，文件框右侧的小箭头只是上传提示，不需要再点击独立的“上传”按钮。选择文件后，还要点击“追加数据”，系统才会真正处理文件。

### 6.2 推荐操作顺序

1. 准备新增时间窗口的完整订单文件，以及可选的库存文件。
2. 选择文件，点击“追加数据”，并确认操作。
3. 等待页面提示“数据追加并完成全部模型训练”。
4. 检查右上角“数据至”日期是否更新到订单文件中的最新有效日期。
5. 返回“销量预测”进行抽样验证；只有需要单独重训时才使用下方模型训练按钮。

点击“追加数据”后会先更新数据和特征，随后**自动训练全部模型**。页面会持续显示执行状态，模型在训练期间会锁定服务，预测请求需要等待。已选择但尚未提交的订单或库存文件，可点击文件框右侧的 `×` 删除并重新选择。

### 6.3 多久追加和训练一次

建议每周追加一次并训练全部模型。业务稳定时可两周训练一次；旺季、大促前后或销售模式变化明显时，建议每周训练。

数据可以不连续、重复追加，也可以补录历史数据。系统按 `date + sku + site` 去重，同一天同一 SKU/站点保留新上传的值。补录旧数据不会让页面顶部的数据截止日期倒退。

为避免误覆盖，请注意：

- 尽量上传完整的一天或完整时间窗口，不要只上传同一天的一部分订单。
- 重复日期会用本次聚合结果覆盖旧值，因此“部分订单”可能把完整日销量覆盖成较小值。
- 日模型预测起点距离最新数据超过 14 天、周模型超过 4 周时，后台会提示精度可能下降。

### 6.4 订单文件格式

支持两种格式。

**格式 A：Amazon 订单/结算明细**

系统会使用这些关键列：

- `type`
- `date/time`
- `sku`
- `quantity`
- `marketplace`
- `product sales`
- `promotional rebates`
- `shipping credits`

可以直接使用与初始化订单文件相同结构的后续增量数据。

**格式 B：简化日销量表**

至少包含：

| date（或“日期”） | sku | site（或“站点”） | sales（或“销量”） |
| --- | --- | --- | --- |
| 2026-07-01 | YU298B | US | 6 |

可选列包括 `avg_price、avg_discount、order_count、daily_revenue、inventory`。

### 6.5 库存文件格式

标准格式至少包含 `date、sku、inventory、site`，也兼容当前库存明细中的中文列名：

- `时间` 或 `日期`
- `SKU`
- `库存数量` 或 `库存`
- `站点`；当前全量库存表中无标题的最后一列也可识别为站点

库存站点为 `EU` 时，系统会展开到 `DE、FR、IT、ES、NL` 五个欧洲站点。

`update` 目录中的两份文件是当前系统的全量初始化数据，可以用于独立测试环境重新初始化；生产页面追加时，不建议再次上传整份全量文件。本次 append 测试可上传 `update/append_test/append_orders_20260624_20260630.xlsx` 和对应库存文件；生产追加应使用当前页面“数据至”之后的新时间窗口，或者需要修正的完整历史窗口。

API 业务日志位于 `logs/api.log`，按 10 MB 轮转并保留 5 个历史文件。可使用 `tail -f logs/api.log` 实时查看 append 前后日期、行数、新增/覆盖量和训练耗时。

## 7. 训练按钮的区别

| 按钮 | 更新内容 | 何时使用 |
| --- | --- | --- |
| 仅训练周模型 | 周预测模型 | 只关心周预测，或周模型需要单独重训 |
| 仅训练日模型 | 日预测模型 | 只关心日预测，或日模型需要单独重训 |
| 训练全部模型 | 日模型和周模型 | 每次常规数据追加后推荐使用 |

两种模型的数据来源相同，但训练粒度和特征不同：周模型学习周汇总规律，日模型学习逐日规律和星期波动。因此“训练全部模型”实际上会依次训练两套模型。


## 8. 后台日志与故障排查

在服务器终端实时查看 API 日志：

```bash
sudo journalctl -u sales-forecast-api.service -f
```

查看最近 200 行日志：

```bash
sudo journalctl -u sales-forecast-api.service -n 200 --no-pager
```

常见情况：

| 现象 | 处理方法 |
| --- | --- |
| 找不到 SKU/站点 | 检查拼写、站点，并确认该组合有历史数据 |
| 新品无法预测 | 使用复杂业务预测，填写新品基准日销量或参考 SKU |
| 追加按钮不可点 | 必须先选择订单文件；库存文件不能单独追加 |
| 追加后日期没变化 | 检查文件是否只有旧日期、无有效订单，或是否上传了库存但订单没有新日期 |
| 追加后预测模式没变化 | 等待“数据追加并完成全部模型训练”的提示；若训练失败，查看后台日志 |
| 训练时页面等待 | 属于正常现象；训练完成前预测请求会排队 |
| 状态显示模型不完整 | 点击训练全部模型；若失败，查看后台日志中的具体错误 |

平时预测：销量预测 → 选择天/周/复杂业务 → 填写参数 → 开始预测
