# FurniScope 管理后台重设计规划

## 1. 产品定位

管理后台不是业务驾驶舱，而是仅供 `admin` 使用的平台控制中心。管理员负责用户状态、模型路由、Prompt 版本、算力参数、运行诊断和审计，不代替 `user` 进行产品判断或业务确认。

## 2. 当前问题

1. 诊断组件使用 `workspace`，样式目标却是 `admin-workspace`，造成主体布局失效和大面积空白。
2. 用户、模型和 Prompt 三个模块只是通用占位列表，没有呈现真实字段、状态和管理动作。
3. 页面缺少清晰的首屏任务：管理员看不到系统是否健康、哪里异常、下一步要处理什么。
4. 筛选、指标和操作挤在同一行，缺少信息分组；宽屏仍出现裁切，响应式策略不足。
5. 诊断缺少失败聚合、阶段耗时、模型调用、版本束和控制事件等关键上下文。
6. 缺少配置发布、版本比较、二次确认、审计记录和失败恢复等完整状态。

## 3. 总体信息架构

后台保持一个 `/admin` 页面，包含四个一级管理域：

1. 用户管理
2. 模型路由与算力
3. Prompt 版本
4. 工作流诊断

不增加 RBAC 矩阵、部门、岗位和审批流。角色始终只有 `user`、`admin`。

## 4. 全局布局

### 左侧独立管理导航

- FurniScope 品牌与“平台管理模式”琥珀色标识。
- 返回 AI 工作台、用户管理、模型与算力、Prompt 版本、工作流诊断。
- 底部系统健康卡：服务状态、最近检查时间、异常数量。
- 管理导航和业务导航视觉相关但明确分区，避免误以为管理员正在操作业务任务。

### 顶部栏

- 当前企业或平台范围。
- 环境标识：生产 / 测试。
- 数据更新时间和刷新状态。
- 审计记录入口、通知、管理员身份。

### 内容结构

四个模块统一使用：

`页面标题与说明 → 关键指标 → 筛选与主要操作 → 主表/配置画布 → 右侧详情抽屉`

内容最大宽度不锁死；表格允许横向滚动，但标题、筛选和主要操作保持可见。

## 5. 用户管理

### 首屏指标

- 用户总数
- 已启用
- 已停用
- 近 30 天活跃

### 主表

字段：姓名、邮箱、企业、角色、账号状态、最近登录、创建时间、更新时间。

筛选：关键词、企业、角色、状态、最近登录时间。

### 详情抽屉

- 基本身份与租户范围
- 最近登录和安全状态
- 最近管理变更
- 账号状态操作

### 关键交互

- 新建用户
- 将角色在 `user/admin` 之间切换
- 启用或停用账号
- 停用、角色变更均二次确认，并展示影响范围
- 保存后显示“审计已记录”

## 6. 模型路由与算力

### 首屏指标

- 已启用路由数
- 路由健康率
- 今日模型调用量
- 今日 Token / 预算使用率

### 主工作区

左侧是任务类型或分析阶段列表：理解产品、研究市场、评估机会、生成建议、报告生成、Embedding、Rerank。

中央展示当前路由链：

- 主模型
- 回退模型顺序
- 超时
- 最大重试次数
- 批大小
- 并发上限
- 当前状态和更新时间

右侧配置抽屉编辑 `compute_config`，提供表单模式与 JSON 模式切换。

### 安全与发布

- 不展示或接收 API Key。
- 配置校验通过后才能启用。
- 保存前展示变更差异和对新任务的影响。
- 已运行任务继续使用被冻结的版本束。

## 7. Prompt 版本

### 首屏指标

- Prompt 模板数
- 已发布版本数
- 草稿数
- 最近 7 天 Schema 失败率

### 主表

字段：Prompt code、任务类型、当前版本、状态、输出 Schema、创建人、更新时间。

### 编辑与比较

- 全屏抽屉创建新版本。
- 左侧模板内容，右侧输出 Schema 和变量说明。
- 支持与上一版本做并排 Diff。
- 状态：草稿、已发布、已停用。
- 发布前运行变量、JSON Schema 和样例输出校验。
- 发布后的版本只读，只能创建新版本或回滚。

## 8. 工作流诊断

### 首屏健康摘要

- 今日运行总量
- 成功率
- 失败率
- 进行中
- P95 总耗时
- 当前告警

增加 24 小时成功率趋势和失败阶段分布，使管理员先发现问题，再进入记录排查。

### 运行列表

筛选：时间、企业、产品、状态、失败阶段、任务 ID。

字段：任务 ID、租户、产品、五阶段状态、当前阶段、总耗时、重试次数、版本束、更新时间。

### 诊断详情抽屉

采用五个内部页签：

1. 阶段时间线
2. 告警与部分失败
3. 模型调用
4. Checkpoint 与控制事件
5. 脱敏请求/响应

阶段时间线展示 attempt、耗时、错误码和恢复能力；模型调用展示 provider、model、Prompt 版本、Token、耗时和 Schema 结果，不展示 Prompt 正文、密钥或租户商业正文。

### 安全控制

- 可重试时显示“安全恢复”。
- 严重异常允许“安全停止”。
- 两项操作均要求二次确认和审计原因。
- 存在待用户确认时，禁止管理员跨过或代答。

## 9. 视觉规范

- 保留深海军蓝、青绿色和琥珀色管理员标识。
- 页面背景使用浅灰，内容卡片使用白色；减少无意义大卡片。
- 正文最小 12px，表格主体 12–13px，标题 20–24px。
- 表格行高 48–56px，控制高度 36–40px。
- 成功、警告、失败除颜色外同时使用图标和文字。
- 详情抽屉宽 420–520px，可调整宽度。
- 配置和日志使用等宽字体，支持复制但默认脱敏。

## 10. 页面状态

每个 Tab 独立处理：加载骨架、无数据空态、筛选无结果、接口失败、权限不足、保存冲突和保存成功。

- 无模型路由：提示创建配置，不虚构默认模型。
- 无 Prompt：提示创建第一个版本。
- 无诊断结果：引导输入任务 ID 或放宽时间范围。
- 403：立即离开后台并提示无权限。
- 保存失败：保留所有编辑内容并定位具体字段。

## 11. 实施顺序

### P0：恢复可用性

- 修复诊断容器类名和宽屏布局。
- 让诊断表、指标和详情抽屉正常显示。
- 补齐四个 Tab 的可靠切换、加载、空态和错误态。

### P1：补齐核心管理闭环

- 完成用户管理表格与详情抽屉。
- 完成模型路由链和算力配置抽屉。
- 完成 Prompt 版本列表、创建、Diff 和发布确认。
- 完成诊断时间线、模型调用和安全恢复流程。

### P2：增强运营效率

- 趋势图、失败聚合和成本分析。
- 保存视图、批量导出、审计记录检索。
- 更完善的键盘操作、响应式布局和可访问性验证。

## 12. 验收标准

- 任意 Tab 首屏都能回答“当前状态如何、哪里需要处理、下一步做什么”。
- 四个模块不再使用通用占位数据结构。
- 所有写操作可追溯，并说明只影响新任务或具体账号。
- 任何页面都不暴露密钥、Prompt 正文或未经授权的租户数据。
- 管理员不能代替用户完成业务确认。
- 1280px、1440px 和 1920px 宽度下无主体空白、裁切或操作栏溢出。
